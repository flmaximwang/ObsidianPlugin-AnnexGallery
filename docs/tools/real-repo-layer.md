# 真仓库层：真 git + 真 git-annex，但不碰你的数据

这一层在 `os.tmpdir()` 里现造仓库，跑真的 `git` / `git annex`，判的是**行为与数据安全**，
不是 UI。它比桩层贵（要装 annex、要建仓），但能抓到桩层永远抓不到的东西：退出码骗人、
annex 对不需要动的文件不说话、`git add` 被 annex 过滤器截回去。

## 共同结构

- **临时仓库 + 合成内容**：每个工具自建目录树（图片、`.md`、缩略图），跑完删干净。
  annex 的对象文件是只读的，删除前要先 `chmod -R u+w`，否则会半途失败。
- **环境隔离**：显式 `cwd`、剥掉代理变量（`HTTP(S)_PROXY` 会让 git/annex 静默失败）、
  需要测「全局配置污染」时用临时 `GIT_CONFIG_GLOBAL` 指向一个假文件 —— **绝不碰**真的 `~/.gitconfig`。
- **缺依赖即 SKIP**：没有 `git annex` / `magick` 时打印 SKIP 并以 0 退出。
- **判据会红**：断言失败累计 `FAIL`，结束时非零退出。

## 各工具判什么

### `verify-init.cjs`（`npm run verify:init`）—— 初始化 gallery

- **幂等**：合规仓库上再跑一次 ⇒ 零写入（内容哈希前后一致、无新提交、配置未动）。
- **按步补齐**：非 git 目录 → 只 `git init`；非 annex → 补 `git annex init`；已合规 → 不动。
- **设置收敛**：annex 分支上的 `annex.addunlocked`、本机覆盖、`annex.thin` 三条各自「偏离才修」，
  并断言**本机覆盖压过分支**时的真实后果（新文件以 `120000` 还是 `100644` 入库）。
- **规则文件合并**：只追加缺的行，已有行一字不改；重复运行不多写一个字节。

### `verify-annex-ops.cjs`（`npm run verify:annex`）—— 6 个 annex 菜单操作

- 造出「图片进 annex、`.md`/缩略图进 git、另一个仓库有副本、一个文件只有本地一份」的局面。
- 断言：预览不动字节、真丢释放字节、唯一副本被挡下、目录之外不受影响、`.md` 与缩略图逐字节未动、
  非仓库目录报错退非零。
- 也走一遍**插件路径**（菜单 → 弹窗 → 确认），避免「核心对了、接线错了」。

### `verify-sidecar-overwrite.cjs`（`npm run verify:sidecar`）—— 生成元数据重跑

- 四条路径：`--plan` 不写盘、默认只补缺失、`--overwrite` 覆盖重算、脏文件保护（改过的 sidecar
  不被静默覆盖）。
- 断言的是「哪些文件被写、写了什么」，不是「跑了不报错」。

### `status-check.cjs`（`npm run verify:status`）—— 状态栏三个数字

- 在临时 annex 仓库里构造未提交 / 未跟踪 / 未入库 largefiles 三种局面，断言三个计数的口径。
- 只判数字与解析，不判颜色与几何（那是真机层）。

### `remotes-check.cjs`（`npm run remotes`）—— remote 设置的读写

- 断言「插件加载时扫仓库补设置、同名不覆盖手改的地址、初始化时 `add` / `set-url` / 原样不动」
  三条语义，全部落在一个真 git 仓库的配置上。

## 什么时候该写在这一层

只要答案取决于**真实工具的行为**（git/annex 的退出码、过滤器、路径解析、对象存储），就必须写
在这一层。写在桩层的，只能是「我们自己的代码怎么调这些工具」。
